## 1. 目标

做一个本机安装的 Chrome 插件。打开一篇英文文章，点一下工具栏里的插件图标，
页面上每个正文段落下方出现一段中文译文，原文保留。翻译由个人 LLM Router
（OpenAI 兼容接口）完成，模型固定为 `cuiyang/gpt-6-luna`。

验收用的样例页面：<https://claude.dev/blog/solving-code-review-at-anthropic/>。

## 2. 用户看到的行为

1. 第一次使用前，用户打开插件设置页，粘贴 API key，保存。endpoint 与模型名已预填。
2. 在文章页点一下插件图标。图标角标显示进度百分比，例如 `45%`（角标最多显示 4 个字符，放不下「已译/总数」）。
3. 译文按批次逐条出现在对应原文段落的正下方，不等整篇翻完。译文块的字号、行高与原文一致，颜色跟随原文但透明度降到 72%（这样深色和浅色网页上都比原文略浅），与原文之间留窄间距。
4. 翻完后角标清空。有任何一批失败的话，角标停在红色 `ERR`，直到下一次点图标。
5. 翻译完成后再点一次图标，页面上所有译文块移除，恢复原页。
6. 翻译进行中再点一次图标，取消剩余批次，正在等待返回的请求也中止，已出现的译文保留，角标清空。准备阶段（注入脚本、定位段落，通常不到 1 秒）内的再次点击被忽略，避免双击开出两份翻译。
8. 可以在多个标签页各自翻译，互不影响。角标、进度、取消都只作用于当前标签页。
7. 未配置 key 时点图标，自动打开设置页，并在设置页顶部提示「请先填写 API key」。

## 3. 不做的事

- 不做划词翻译、不做弹窗翻译。
- 不翻译代码块、行内代码、链接地址、图片说明以外的图片内容。
- 不翻译页面的导航栏、侧边栏、评论区、页脚。
- 不缓存译文。关掉页面再打开要重新翻。
- 不上架 Chrome 商店，不做自动更新。
- 不支持英文以外的源语言，也不做语言检测。页面不是英文时照样发给模型，结果不保证。
- 页面由前端框架重新渲染导致译文块被清掉时，不自动重插。再点两次图标即可。
- 文本匹配（5.1 节）失配的段落直接跳过，不做相似度匹配，也不提示。

## 4. 结构

插件用 Manifest V3，由四部分组成。

| 部分 | 文件 | 职责 |
|---|---|---|
| 清单 | `manifest.json` | 声明权限、各脚本的入口 |
| 纯逻辑 | `lib.js` | 分批、返回校验、段落选取、文本匹配。不依赖 Chrome API。后台用 `importScripts` 加载，内容脚本按注入顺序先加载，单元测试在 Node 里直接 `require`。文件末尾按环境把导出挂到 `module.exports` 或 `globalThis.CT` |
| 后台脚本 | `background.js` | 响应图标点击；持有每个标签页的翻译状态；向 LLM Router 发请求；更新角标 |
| 内容脚本 | `content.js` + `readability.js` | 纯渲染层：在页面里收集段落、插入和移除译文。不持有状态 |
| 设置页 | `options.html` + `options.js` | 填写 endpoint、模型、key |

点击图标后的流程：

1. 用户点图标。Chrome 调用 `background.js` 里注册的 `chrome.action.onClicked`。
2. `background.js` 读取存储里的配置。key 为空就打开设置页并结束。
3. `background.js` 查自己内存里以 `tabId` 为键的状态表。该标签页正在翻译，就置取消标志、中止在途请求、清空角标，结束。
4. 否则 `background.js` 用 `chrome.scripting.executeScript` 注入 `readability.js`、`lib.js`、`content.js`（每次点击都注入；内容脚本用 `window.__ctLoaded` 防止重复注册监听），然后向内容脚本发消息 `toggle`。
   内容脚本看页面上有没有 `.ct-translation`：有就全部移除并回复 `{removed:true}`；没有就选取段落，回复 `{paragraphs:[...]}`。
5. 后台把段落分批，每批发一次翻译请求。每批返回后，后台把该批的译文连同段落序号发给内容脚本，内容脚本插入译文块，后台更新角标。
6. 全部批次完成或被取消后，后台清空角标。

内容脚本与后台之间只传纯文本和序号，不传 DOM。「正在翻译」这个状态只在后台有一份，内容脚本不保存。

后台是 MV3 的 service worker，空闲约 30 秒会被 Chrome 终止。一次非流式 fetch 超过 30 秒没返回也算空闲，一批长段落的翻译有可能超过 30 秒。所以翻译进行中每 20 秒调一次轻量扩展 API（`chrome.runtime.getPlatformInfo`）重置空闲计时，结束后停掉。状态表只在内存里，不做持久化。

权限：`activeTab`、`scripting`、`storage`，`host_permissions` 里写 `http://172.24.201.32/*`，`optional_host_permissions` 里写 `<all_urls>`。
用户在设置页把 endpoint 改成别的主机并保存时，设置页调 `chrome.permissions.request` 申请该主机；用户拒绝则保存失败并提示。
翻译请求必须从后台脚本发出，因为页面本身的 CSP 可能禁止内容脚本向站外发请求，
而后台脚本只受 `host_permissions` 约束。

## 5. 正文段落的选取

### 5.1 用 Readability 定范围，用文本匹配回到真实页面

Readability 是 Mozilla 开源的正文提取库（Firefox 阅读模式用的那个），
输入整个文档，输出正文区域的 DOM 副本。它只处理副本，不碰真实页面，
所以不能直接拿它的输出往页面里插译文。

做法分三步：

1. 深拷贝 `document`，交给 Readability，得到正文副本。
2. 在正文副本里按 4.2 节的规则收集段落元素，取每个段落的规范化文本（合并连续空白、去首尾空白）。
3. 在真实页面里按同样的规则收集候选段落元素，建一张「规范化文本 → 真实元素」的表；
   用第 2 步的文本逐个查表，查到的真实元素就是要翻译的段落。文本相同的多个元素只取第一个出现的。

查不到对应真实元素的段落跳过。Readability 把文章大标题单独放在 `article.title` 里，不在正文副本中；在真实页面找文本相同的 `h1` 补进段落列表最前面。
Readability 返回空（判定页面没有正文）时，向用户提示
「没有找到可翻译的正文」并结束。

### 5.2 段落的定义

以下标签算一个段落：`p`、`h1` 到 `h6`、`li`、`blockquote` 里直接的文本、`td`、`th`、`figcaption`。

跳过规则：

- 规范化文本不足 2 个单词的跳过（例如只有「Share」「Next」）。
- 元素本身是 `pre`、`code` 或处于其内部的跳过。
- 一个段落元素内部还套着别的段落元素时（例如 `li` 里有 `p`、嵌套列表、`td` 里有 `p`），跳过外层只取最内层，避免同一段文本取两次。
- 段落内的行内代码（`code`）和链接保留在文本里原样发给模型，由 prompt 要求模型原样保留。

### 5.3 译文块

译文块是一个 `div`，class 为 `ct-translation`，插在对应段落元素之后，作为兄弟节点。
标题段落的译文块用与标题相同的标签名（`h2` 的译文仍是 `h2`），以继承页面标题样式。
`li`、`td`、`th` 的译文块插在元素内部末尾，放在外面会破坏列表结构或让表格多出一列。
译文块都带 `data-ct-index` 属性记录段落序号。移除译文时按 class 全部删除。

## 6. 翻译请求

### 6.1 接口

`POST {endpoint}/chat/completions`，OpenAI 兼容格式。endpoint 默认 `http://172.24.201.32:8080/v1`。

2026-10-18 用 curl 实测的响应结构（截去无关字段）：

```json
{"choices":[{"message":{"role":"assistant","content":"{\"t\":[\"你好，世界。\",\"代码审查很难。\"]}"}}],
 "model":"gpt-6-luna-2026-09-22"}
```

请求里带 `"response_format":{"type":"json_object"}`，模型会返回合法 JSON，实测可用。

### 6.2 分批

按累计字符数分批，一批不超过 3000 个字符，且不超过 20 段。
同一时刻最多 3 批并发。批内顺序与页面顺序一致，批与批之间谁先返回谁先插入。
每批请求超时 60 秒，用 `AbortController` 实现；取消翻译时同一个 controller 中止在途请求。超时按第 8 节的网络错误处理。

### 6.3 Prompt

system：

```
You translate English web article paragraphs into Simplified Chinese.
Input is a JSON array of strings. Output a JSON object {"t": [...]} with the
translations in the same order and the same length.
Keep inline code, URLs, product names, and people's names unchanged.
Translate naturally; do not add notes or explanations.
```

user：段落文本数组的 JSON 字符串。

### 6.4 返回校验

解析 `content` 为 JSON，取 `t`。`t` 不是数组、或长度与输入段数不同，按该批失败处理（见第 8 节）。
不做部分采用。

## 7. 设置页与存储

设置页三个字段，存在 `chrome.storage.local`：

| 字段 | 存储 key | 默认值 |
|---|---|---|
| endpoint | `endpoint` | `http://172.24.201.32:8080/v1` |
| 模型 | `model` | `cuiyang/gpt-6-luna` |
| API key | `apiKey` | 空 |

key 只在 Chrome 本机的扩展存储里，不写进仓库里的任何文件。`my_scripts` 仓库每晚自动同步到 GitHub，
仓库里只能有预填的 endpoint 和模型名。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| key 为空 | 打开设置页并提示，不发请求 |
| 网络不通、超时或 HTTP 非 2xx | 该批失败。该批每个段落下各插一个译文块，内容为「翻译失败：{状态码或错误信息}」。其他批继续，进度照常更新；全部结束后角标停在红色 `ERR` |
| 返回 JSON 解析失败或长度不符 | 同上，错误信息为「返回格式错误」 |
| 页面是 `chrome://` 等不可注入的页面 | 角标显示 `N/A`，3 秒后清空 |
| 设置页改 endpoint 到新主机，用户拒绝权限申请 | 不保存，设置页提示「未获得该地址的访问权限」 |
| Readability 找不到正文 | 角标显示 `0`，3 秒后清空 |

失败批不自动重试。用户点两次图标（移除、再翻译）即重来。

## 9. 方案选择记录

### 9.1 翻译服务

| 方案 | 结论 |
|---|---|
| 个人 LLM Router，模型 gpt-6-luna | 选用。用户指定。 |
| Claude API / DeepL / Google 翻译 | 不选。用户已有可用的 Router，不想再接服务。 |

### 9.2 正文定位

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| Readability 定范围 + 文本匹配回真实页面 | 覆盖博客、新闻、文档站；排除导航和评论可靠 | 多一步匹配；极少数页面漏段 | 选用 |
| 只按 `article` / `main` 标签取 | 实现简单 | 很多站没有这两个标签，或标签里包含评论区 | 不选 |
| 翻译整页所有 `p` | 最简单 | 导航、页脚、评论全被翻，噪音大，请求量也大 | 不选 |

### 9.3 请求发起位置

| 方案 | 结论 |
|---|---|
| 后台脚本发请求 | 选用。不受页面 CSP 限制。 |
| 内容脚本直接 fetch | 不选。样例站这类带严格 CSP 的页面会拦截。 |

## 10. 测试用例

| 编号 | 场景 | 输入 | 期望 |
|---|---|---|---|
| T1 | 样例页翻译 | 打开样例页，配好 key，点图标 | 每个正文段落和标题下出现中文；导航、页脚无译文；代码块无译文 |
| T2 | 再点移除 | T1 完成后再点图标 | 所有 `.ct-translation` 消失，页面与原始一致 |
| T3 | 进行中取消 | T1 翻到一半点图标 | 剩余批次不再发出，在途请求中止，已有译文保留，角标清空 |
| T4 | 未配 key | key 为空，点图标 | 打开设置页，顶部有提示，无请求发出 |
| T5 | 后台返回长度不符 | mock 返回 `t` 少一项 | 该批段落下显示「翻译失败：返回格式错误」，其他批正常 |
| T6 | HTTP 500 | mock 返回 500 | 该批每段显示失败，其他批正常，结束后角标 `ERR` |
| T7 | 段落选取 | 含 `li>p`、`pre>code`、单词「Share」的 HTML 片段 | `li` 只取一次；`pre` 内不取；「Share」不取 |
| T8 | 文本匹配 | 真实页面两个段落文本相同 | 只有第一个被翻译 |
| T9 | 分批 | 50 段、总 8000 字符 | 批数符合 6.2 规则，每批不超 3000 字符且不超 20 段 |
| T10 | 不可注入页面 | 在 `chrome://extensions` 点图标 | 角标 `N/A`，无报错弹窗 |

T5 到 T9 为单元测试，用 Node 下的 `vitest` 跑，DOM 部分用 `jsdom`。
T1 到 T4、T10 为手工验收。
