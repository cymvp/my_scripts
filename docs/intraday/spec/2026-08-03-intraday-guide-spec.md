## 1. 它做什么、不做什么

**做**：在你已经决定要买或要卖的前提下，回答「挂在哪、买多少、止损放多宽、什么时候动手」，
并对照 `交易纪律.md` 逐条做纪律检查。

**不做**：不预测方向，不输出看涨看跌，不给目标价，不给买卖信号。

**理由**：方向类检验全部落空——15 个日线格子、71 个日内格子、12 个量能格子，
BH 校正后无一通过；15 个日内策略在测试期全部失败，训练期最好的 +71.1% 在测试期变成 −21.8%。
skill 里出现方向预测，等于把已经被数据否掉的东西重新放进来。

**数据来源**：`~/projects/my_data/trading/查表手册.md` 的表 A / B / D / E。
skill 不自己推导统计结论，只查预先算好的基准文件。

## 2. 命令行接口

```
python3 intraday_guide.py advise \
    --hold 300308=10万 --hold 002185=10万 \
    --cash 20万 \
    --t-cash 10万 \
    --total 40万 \
    [--risk 1%] [--at 10:30]
```

| 参数 | 必填 | 含义 |
|---|---|---|
| `--hold 代码=金额` | 是，可重复 | 每只票的当前持仓市值。代码用六位数字，也接受股票名 |
| `--cash` | 是 | 账户当前现金总额 |
| `--t-cash` | 否 | 今天准备用于做 T 的可支配现金；不填则等于 `--cash` |
| `--total` | 否 | 总资产；不填则由持仓合计加现金推出 |
| `--risk` | 否 | 单笔风险预算，默认 1%（单笔最大回撤不超过总资产的 1%） |
| `--at` | 否 | 指定时点做回溯分析，默认取当前时间 |

**持仓手工输入，不落盘。** 不写配置文件，避免持仓数据进入仓库。
**本文档里的金额全部是示意值，不是真实持仓**——这个仓库是公开的。

保留现有子命令：`build`（重建统计基准）、`--stat`。

## 3. 数据结构

```python
Holding      = {code, name, value}           # 单只持仓
Snapshot     = {code, name, trend, open, last, high, low,
                pred_amp,                    # 预测振幅：过去10日振幅中位
                amp_cell,                    # 落在表A的哪一格
                walked_amp,                  # 盘中已走振幅
                pos_vs_open,                 # 当前价相对今开
                implied_full_amp,            # 由已走振幅反推的全天振幅
                remain_room}                 # 剩余空间
Baseline     = {table_a, table_b, table_d, table_e}   # 只有四张，见下方说明
Allocation   = {code, weight, amount}        # 风险平价分配结果
CheckResult  = {id, title, status, detail}   # status ∈ pass / fail / ask / info
```

**基准文件** `intraday_baseline.json` 的结构：

```json
{
  "built_at": "2026-08-03",
  "daily_range": ["2023-06-30", "2026-07-31"],
  "m30_range": ["2026-01-07", "2026-07-31"],
  "table_a": {"下跌": {"6~8%": {"n": 935, "down": {"1": 76.4, ...}, "up": {...}}}},
  "table_b": {...}, "table_d": {...}, "table_e": {...}
}
```

**只有四张表。** 原表 C（限价买单收益差）2026-08-03 降级——它的成交率列就是表 A 的
向下触及概率（同一个数在三处重复），独有的收益差列收敛成一条规则（多数情况别挂限价），
盘中不需要查；而且 `build` 从来没有生成过它。
「常数组·开盘价在区间的位置」同理，是三个固定数字，不是查表，写在文档里就够。

**表名 A / B / D / E 是标识不是序号，D 和 E 不改名，避免打断既有引用。**

## 4. 核心逻辑

### 4.1 取数

| 用途 | 数据源 | 取多少 |
|---|---|---|
| 趋势状态、预测振幅 | 腾讯前复权日线 | 每只票 300 根 |
| 当日分时（已走振幅、当前价） | 新浪 30 分钟线 | 当日 |
| 板块普涨普跌 | `intraday_collector.breadth_all()`（从已积累的 30 分钟数据算） | 全部历史 |

**同一分析只用同一个数据源**——新浪 30 分钟线是不复权原始价、腾讯日线是前复权，
混算会出错（2026-08-02 踩过，寒武纪出现 +60% 的假日内涨幅）。
**因此预测振幅、趋势状态一律用日线算；已走振幅、当前价一律用当日 30 分钟线算，两边不交叉。**

### 4.2 单票计算

```
pred_amp   = median(过去10个交易日的 (最高-最低)/开盘)
trend      = 由 (昨收 - 前60日最高收盘)/前60日最高收盘 分档
amp_cell   = pred_amp 落在 0~3% / 3~4% / 4~6% / 6~8% / >8% 哪一档
walked_amp = (今日至此刻最高 - 今日至此刻最低) / 今开
implied_full_amp = walked_amp / 表E[trend][当前时点].已走%
remain_room      = 表E[trend][当前时点].剩余空间
```

**校准检查**：若 `implied_full_amp` 与 `pred_amp` 相差超过 50%，输出提示
「今天偏离常态，盘前定的止损和仓位要重新审视」。

### 4.3 现金分配（风险平价）

```
weight_i = (1 / pred_amp_i) / Σ(1 / pred_amp_j)
amount_i = t_cash × weight_i
```

**算例**：可做 T 现金 50 万，三只票预测振幅 6.83% / 5.00% / 4.00%。
倒数为 0.1464 / 0.2000 / 0.2500，合计 0.5964。
分配 12.3 万 / 16.8 万 / 21.0 万。**波动最大的分得最少，三笔的风险敞口才相当。**

**方案选择记录**：

| 方案 | 优点 | 缺点 | 采用 |
|---|---|---|---|
| 平均分配 | 简单 | 高波动票的风险敞口远大于低波动票 | 否 |
| **风险平价（按预测振幅倒数）** | 三笔风险敞口相当 | 会把最多的钱分给最温吞的票 | **是** |
| 按持仓比例分配 | 贴近现有结构 | 会放大已经超限的仓位 | 否 |

### 4.4 仓位上限

```
仓位上限_i = total × risk / 止损宽度_i
```

止损宽度由用户选，skill 给出各档的触发概率、触发后回到开盘上方的比例、
以及两者相乘的**无效止损概率**（最终要看的数），让用户自己取舍。

### 4.5 表 B 扩展（2026-08-03 追加）

表 B 的主结果是**无效止损概率** = 触发概率 × 触发后收盘回到开盘上方的比例，
也就是「当天既被止损卖出、收盘价又回到了开盘价之上」的概率。
除此之外再加三种情形，**全部以触发价为比较基准**：

| 情形 | 触发条件 | 「亏」的定义 |
|---|---|---|
| 低位买入 | 当日最低 < 开盘 ×(1−X) | 买高了：收盘 < 成交价 |
| 高位卖出 | 当日最高 > 开盘 ×(1+X) | 卖亏了：收盘 > 成交价（卖早了） |
| 高位买入（追高） | 同上 | 买高了：收盘 < 成交价，与上一行互补 |

**实测结论：几乎所有格子都落在 46%~57%，成交后到收盘的中位收益在 ±0.2% 以内。**
唯一例外是「下跌 + 预测振幅 >8%」：买高了 58.5%~62.1%，中位 −0.84% 到 −1.25%。

**skill 在这一格必须同时输出两句话，否则会误导：**
表 C 说这里挂 −3% 限价比开盘市价买好 +0.817%；表 B 扩展说这里成交后到收盘中位仍是 −0.88%。
**限价比市价好，但绝对上仍然亏——当天买入这个动作本身就是负期望。**

### 4.6 表 D 用全池，不按单只股（2026-08-03 追加验证）

同一套方差分解方法（各股实际离散度 vs 纯抽样噪声）：

| 指标 | 24 格里有真实个股差异的 | 差异幅度 | 基准值量级 |
|---|---|---|---|
| 段内为正比例（方向类） | **2 / 24** | — | 38%~53% |
| 段振幅占全天 | 17 / 24 | 1.4~4.2pp | 17%~72% |
| 成交量占比 | 18 / 24 | 0.4~3.4pp | 6.6%~33.9% |

**方向类的个股差异几乎全是噪声**（每股每格只有 25~40 个样本，纯噪声标准差就有 7.3~8.1pp）。
形状类和量能类有真实差异但是二阶的——四只票的段振幅占全天与全池差距普遍在 3pp 以内。

**决定：表 D 一律用全池。** 唯一例外是上涨趋势的开盘段振幅占比（真实差异 4.2pp），
skill 在该股样本 ≥25 个交易日时附带显示它自己的值作为参考，不替换全池值。

### 4.7 板块集中度

38 只票的行业归属已在 `intraday_guide.POOL` 的 SECTOR 映射里。
若传入的多只票属于同一板块，输出明确警告：**这不是分散，是加杠杆。**

依据：同日聚类问题——38 只科技股高度同向，同一天的多只票是 1 次独立观察不是 N 次。

## 5. 输出结构

### 每只票一段（五块）

1. **今天是什么日子**：趋势状态、开盘跳空、预测振幅及落在哪一格、当前已走振幅占比
2. **剩余波动空间**：反推的全天振幅、还剩多少、与盘前预测是否一致
3. **当前时点的分段结构**：所处时段的段内为正比例、振幅、振幅/净幅比，
   **对买方和卖方分别写一句**，不能合并成一句
4. **止损与仓位**：各档止损的触发概率、无效止损概率、对应仓位上限
5. **挂单参考**：向下各档的成交概率（买）、向上各档的成交概率（卖）；
   若处于「下跌 + 预测振幅 >8%」这一格，附注表 C 那条待确认的观察及其可信度警告

6. 可做 T 现金的风险平价分配
7. 板块集中度警告
8. 纪律检查（见 §6）

## 7. 基准重算

| 内容 | 数据 | 频率 |
|---|---|---|
| 表 A / B / C、常数组 | 日线 3 年 | **每周一次（周末）** |
| 表 D / E | 30 分钟线，全部已积累数据 | 每周一次 |

**每次重算必须重新计算分格边界，不要沿用写死的数字**——实测振幅水平在 1.5 年里漂移约
0.5 个百分点。

**注意区分两类窗口**：预测振幅用的「过去 10 个交易日」是每次调用现算的，天然滚动，
不需要预存；需要定期重算的只有全池的基准表。

挂 cron：`0 20 * * 6`（周六 20:00 跑 `intraday_guide.py build`）。

## 10. 三个决定（2026-08-03 定，都可改）

**原来这里是三个待确认项，现在给出决定和理由。都是可逆的，不同意随时改。**

### 10.1 参数形式：命令行，不做交互式

skill (`~/.claude/skills/ycui_intraday/SKILL.md`) 负责问用户要持仓，然后拼成命令跑。
工具本身保持命令行、无状态、不落盘。

**理由**：交互式问答放在 skill 层比放在脚本里灵活——skill 可以根据上下文判断哪些
已经问过了；而脚本保持纯命令行，方便回溯（`--at 10:30`）和以后接定时任务。

### 10.2 单笔风险预算默认 1%

**理由**：1% 对应的仓位上限，在预测振幅 6~8% 的票上是「−5% 止损 → 总资产的 20%」。
这个量级和三条硬性上限（单票 ≤25%）自洽，不会出现两条规则互相打架。
用 `--risk` 可以临时改。

### 10.3 不发 Slack

**理由**：`advise` 是交互式使用的，输出要配合用户当时的问题解读；
而 Slack 适合单向推送。定时推送的场景已经由 `ycui_market_advisor` 覆盖。
**更重要的是**：这份输出里含持仓金额，发到 Slack 等于把持仓数据推到第三方服务上。
